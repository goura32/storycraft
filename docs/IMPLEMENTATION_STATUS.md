## 現在の仕様との差分（2026-07-28）

この節は、仕様書と現行コードを読み合わせた記録です。以下はコード・試験・テスト用資料を変更せずに確認した差分であり、仕様を弱めるものではありません。

- V1 はローカル LLM 専用ですが、現行コードは `ollama` に加え `openai`、`openrouter`、`openai_compatible` を LLM 提供者として受け付けます。
- 注意付き巻公開の公開注意種別と、巻公開用原稿冒頭への定型文出力は未実装です。
- 形式不正再呼出し上限到達、修正上限時の注意付き採用、品質上限で停止しない遷移は未実装です。現行コードは工程別設定の再試行を使い、品質上限では停止します。
- 指摘対象だけに修正範囲を制限せず、成果物全体の整合性・品質改善のために置き換える契約は未実装です。現行コードは修正範囲を検証して制限します。
- V1 は公開 CLI を `init`、`run`、`status`、`validate` に限定し、`status`／`validate` は書込み lock を取らない契約ですが、現行コードは `init` を持たず `resume`／`step` を公開し、workspace 引数は `--workspace` ではなく `--out` です。現行 `status` と `validate` は `--json` を持たず raw run-state / `pending_commit` を出力し、active lock を確認せず、`validate` は writer lock 下で動きます。現行 CLI は `ContractError` を一律 argparse の終了コード `2` と人間向け stderr にし、未処理例外は終了コード `1` です。V1 の stderr 一行 JSON と `2|4|5|70|75` の診断別終了コードは未実装です。
- 正本・参照・確定物の不整合を `blocked` のまま再開せず新しい作業場所でやり直す V1 契約は未実装です。現行コードは旧来の復旧・継続経路を持ちます。
- 公開確定の中断を表すテスト用資料は、`current_stage` が現行コードの要求する `publication` ではないため、関連試験が失敗します。
- 巻の引継ぎを作らず、各巻の全場面と継続性更新の確定後に同じ巻単位で公開準備・確定と巻公開用原稿作成を行い、最終巻公開で完了する遷移は未実装です。現行コードは巻の引継ぎ、全巻の完結判定後のシリーズ全体一括公開を行います。

これらは実装修正が必要な差分です。現行コードの公開判断には、仕様書だけでなく、現在の自動試験と配布物の動作確認を用います。

## 確認済みの範囲

- 依頼文またはキーワードの入力から公開用 Markdown 原稿までの V1 の流れ
- 新規実行 `run`、状態表示 `status`、検証 `validate`
- LLM 生成物の採用、場面の確定、公開用原稿のまとめての確定と復旧
- 作業場所の排他制御、不変の成果物、LLM 提供者に依存しない検証・復旧
- 構造化された出力、確認と修正、変更範囲の制約、呼出し記録
- 当時の自動試験 527 件と、隔離した配布物の作成・インストール確認

## 実際の LLM による確認

最初の作品設計を対象に、大規模言語モデル（LLM）による構造化された出力、批評と改稿の繰返し、依頼文の文体指定の保持、修正範囲の制約を確認済みです。

工程ごとの確認形式を追加した後の最終的な実 LLM 再試験は、実行時間を考慮して実施していません。この未実施は自動試験または配布物の動作確認の失敗を意味しません。
